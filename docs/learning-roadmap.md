# CS336 学习路线：有 10 年以上软件开发经验

## 目标与节奏

目标是独立完成“小模型从数据到训练、性能优化、规模预测、后训练”的闭环，并能用实验解释设计取舍。编程年限能减少工程入门时间，但不能替代概率、梯度、张量形状和 GPU 数值计算基础。

建议 14 周，每周 10–12 小时（约 140–168 小时，个人规划而非官方工时承诺）。若尚未接触深度学习，增加 2–4 周基础训练；不要按课程视频播放完毕判断完成。每周约 25% 阅读/推导、55% 实现、20% 测试和复盘。

官方入口：https://cs336.stanford.edu/ 。以本仓库锁定的 Spring 2026 作业 PDF 为验收细则，课表用于安排背景阅读。

## 先做能力诊断（第 1 周）

不必重学通用编程、Git、HTTP 或完整软件工程课程。集中检查：

- Python：迭代器、生成器、上下文管理器、typing、pytest、性能分析。
- PyTorch：广播、einsum/einops、stride/contiguous、autograd、device/dtype、随机种子。
- 数学：矩阵乘法形状、链式法则、对数概率、交叉熵、期望/方差、训练集与验证集区分。
- 手写一个小分类器：解释梯度和 loss，完成单批次过拟合，保存/恢复 checkpoint 后继续训练。

退出条件：能画出前向/反向的张量形状，解释梯度累积和参数更新差别；若做不到，先补对应知识。数学以实验所需为界，不先铺开半年理论课。

## 分阶段安排

| 时间 | 主线与配套课 | 实施顺序 | 验收产物 |
| --- | --- | --- | --- |
| 第 2–5 周 | A1 Basics；课程 1–3，按需读推理内容 | 字节级 BPE → Transformer 组件 → 优化器/训练循环 → 小规模训练/生成 | 上游要求的测试通过；分词 round-trip 与边界样本；小批次过拟合；训练/验证曲线、checkpoint 恢复与生成样例 |
| 第 6–8 周 | A2 Systems；课程 5–8 | 建立 A1 正确性基线 → profile → Triton/FlashAttention2 → 分布式与显存优化 | 正确性误差对比；预热与同步后的吞吐/显存数据；同一硬件同一 shape 的前后对比；解释通信开销 |
| 第 9 周 | A3 Scaling；课程 9、11 | 读 API/训练路径 → 设计小预算实验 → 拟合 scaling law → 留出实验验证 | 原始实验表、拟合脚本/图、外推误差与预算建议；区分实际测量和预测 |
| 第 10–11 周 | A4 Data；课程 12–14 | 文本抽取 → 质量/内容过滤 → 精确和近似去重 → 数据混合 → 固定预算比较 | 逐步保留率、抽样审计、去重统计、相同 tokenizer/训练预算下的验证指标 |
| 第 12–14 周 | A5 Alignment；课程 15–16 | 建立评测 → SFT → 推理任务 RL/GRPO → 对照与误差分析 | SFT/RL 对比、奖励与独立评测指标、失败样本和资源记录；有余力再做可选安全对齐/DPO |

A1 应投入最多连续时间：A2 依赖它的正确模型与训练基线，A4 的数据价值也应通过训练验证。A3 可以在 A2 GPU 实验等待期间阅读，但先掌握 FLOPs、tokens 和 loss 的关系。

A2 提供官方 A1 基础实现，可作为性能实验基线；A4 为保证可比性，官方要求保持提供的训练逻辑。不要把所有作业都替换成自己的训练框架。

锁定的 A4 README 中，最终训练配置使用 8 张 B200。自学时先完成离线数据处理和小规模对照，把完整规模训练作为独立算力里程碑；缩小实验的结论不直接等同于官方最终配置的结果。

## 资深工程师要刻意训练的部分

1. 先推导再编码：每个组件写输入/输出形状、数学式、数值稳定处理和复杂度，避免只把接口拼通。
2. 正确性先于性能：用小张量参考实现、梯度与误差比较排除错误，再做优化；固定 seed 不等于所有 GPU 算法完全确定。
3. 控制变量：比较模型时固定数据/tokenizer/预算，比较系统时固定硬件、dtype、shape、batch 和测量方法。
4. 小实验闭环：先 tiny dataset、单批次过拟合，再扩大训练。不要先建大平台、服务框架或全套 MLOps。
5. 每个作业写一页复盘：假设、方法、结果、失败原因、下次决策；把“跑通”升级为“能解释”。

## 环境与资源策略

Windows 主机用于编辑和 Git；GPU/Triton/分布式部分优先使用 Linux 或 WSL2，并以各作业的锁定环境为准。每个作业各自 `uv sync`，避免合并依赖或擅自统一 Python/PyTorch 版本。

CPU 先完成可运行的组件正确性检查和小样本调试；GPU 用于正式训练与性能测量。A2 的 GPU kernel/多卡实验不能用 CPU 测试代替，A5 的 flash-attn 等依赖应按其 README 分步安装。具体显存和卡数以作业 PDF 的模型与实验配置为准；尚未实测前不承诺某张卡能完成全部作业。

A3 官方 README 区分在校生与自学者：学生 API 使用学号凭据，自学者应走 `uv sync --extra server` 及仓库公开的训练路径。不要假设持有学校 API 权限，也不要随意调用他人的服务。下载完整数据或启动训练前先估算存储、GPU 时长和可接受预算。若暂缺算力，可用明确标注的小规模自建实验理解拟合流程，但不算完成官方规模验收。

## 每周记录与完成标准

建议在 `notes/` 保存每周笔记，在 `reports/` 保存可提交的实验报告。每次实验记录：父仓库/submodule SHA、命令、环境、GPU、数据来源与切分、seed、超参数、tokens、耗时、峰值显存、指标及产物路径。大模型/数据保留在外部存储，记录校验值和下载方式。

- [ ] 基础诊断通过，能独立解释张量形状和梯度。
- [ ] A1：组件、训练和生成按官方手册完成，有验证集证据。
- [ ] A2：优化正确性、测量方法和分布式实验都有证据。
- [ ] A3：有实际观测、拟合和留出验证，明确外推边界。
- [ ] A4：数据处理可复现，有固定预算的质量比较。
- [ ] A5：SFT/RL 评测可复现，奖励与效果分开记录。
- [ ] 最终报告能说明计算、数据、架构和后训练之间的取舍。
